# Changelog

All notable changes to GeoHarness are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- HTTP `Link` headers in `_headers`, as the head tags already promised: every page declares its markdown twin
  (`rel="alternate"; type="text/markdown"`) and llms.txt (`rel="describedby"`), every twin its page
  (`rel="canonical"`). Directory-style sites use two generic `:splat` rules whatever their size (exact rules where a
  generic one would be wrong); the rules are written all or none within Cloudflare's 100-rule cap (warning
  `headers.link_skipped`).
- Generated JSON-LD is one `@graph`: a top-level Organization or Person node (`@id` `<identity.url>#organization`
  or `#person`, with `sameAs`), a `WebSite` node on the home page and the `WebPage`, linked by `@id`. Author JSON-LD
  is still never replaced. New optional `identity.logo` and `identity.email`.
- Advisory audit checks for gaps an independent geo.new audit found and GeoHarness scored as perfect:
  `extract.quotable_sections`, `signals.description_length`, `signals.entity_node`, `signals.website_node`,
  `signals.contact`, `signals.trust_links` and the live `signals.live_link_header` (also in the config-less
  `geoharness audit <url>`). [docs/geo-new-parity.md](docs/geo-new-parity.md), generated by `npm run docs`, maps all
  192 geo.new checks onto GeoHarness with the evidence for each decision.

### Changed

- The advisory category `signals` is titled "Signals (advisory)"; scores of sites without entity JSON-LD, contact
  and trust links or `Link` headers drop accordingly (geo.avarok.net: see the pull request).

- The pre-deploy Lighthouse gate audits the output served by `wrangler dev --local` (or `wrangler pages dev`)
  with the deploy's own config, so `_headers`, `html_handling` and 404 handling apply; lhci's static server
  ignored them and passed a CSP that scored SEO 92 in production.
- `_headers`: a GeoHarness rule whose URL pattern the site already uses is merged into that site rule, so
  `wrangler dev` (last rule per pattern wins) serves the same headers as production.
- Generated Worker `compatibility_date` is 2026-10-30, the newest the pinned wrangler's runtime supports.

### Fixed

- Rewrite rules for every domain, not only the host of `site.origin`: `www.` and other listed hosts answered
  `Accept: text/markdown` with HTML. The zstd Compression Rule covers every domain too. Before deploy, the zone's
  URL Rewrite budget (10 on Free, 25 Pro, 50 Business, 300 Enterprise) is checked against GeoHarness's 3 rules per
  domain plus the zone's other rules, naming them; every domain must be in the zone of `site.origin`'s host.
- A domain that still has its own A/AAAA/CNAME records (a Pages → Workers move) failed only after upload, as
  "wrangler deploy exited with 1". Preflight now finds them before the build and explains the zero-downtime move;
  wrangler and lhci failures report the tool's own `[ERROR]` block and Cloudflare error codes (e.g. 100117).
- Rollback on a migration's first run "rolled back" to the Worker's own earlier failed upload. A version counts as
  the previous production only if one of the domains was a Custom Domain of the Worker before the run; otherwise the
  run says there is no prior production version on the Worker and that the previous host (e.g. Pages) is not
  something GeoHarness can roll back to. Rolling back to the version serving now is refused.
- A local run without `GITHUB_STEP_SUMMARY` and `GITHUB_OUTPUT` built, deployed and verified, then failed writing
  the summary. Both are required inputs of the run now, checked with the others before anything starts.
- sitemap lastmod was missing for built output (gitignored, so git had no date): see `content.sources`.
- `<meta name="build">` is injected at the top of `<head>` (after a charset declaration) instead of its end. The
  live build check reads the first 8,192 characters, so a page with a large inline `<style>` or JSON-LD failed
  verification after deploying and was rolled back, though it served the right build. Found migrating
  thomaspbraun.com (build meta at offset 15,466).
- Markdown twins: icon-only links keep a label (`aria-label`, then `title`, then an inner image's `alt`)
  instead of converting to `[](url)`, and fragment-only links (`#experience`) become `<canonical>#experience`
  in the twin and in `llms-full.txt` instead of pointing into the markdown.
- robots.txt: the site's own groups now carry the configured `Content-Signal` too. A configured group the
  site's file already had (its `User-agent: *` included) was absorbed without the line, so the crawlers that
  read that group never saw the signal. A site group stating a different signal is a `robots.conflict`.
- Security: child processes no longer inherit the action inputs (`INPUT_*`), so the Cloudflare API token no longer
  reaches the site's build command or the install scripts of its dependencies; wrangler still gets it, passed
  explicitly. Found migrating thomaspbraun.com, GeoHarness's first external consumer.
- Verify: a network error on a live request (a reset, refused connection or timeout) is retried 3 times, 2 s
  apart; one that persists names the request and its cause (`GET <url> (<user-agent>, Accept: …): fetch failed:
  read ECONNRESET`) instead of a bare `fetch failed`. A verification that cannot complete, including a build that
  never goes live, now goes through the rollback like a failed one; before, a thrown error skipped the rollback.

### Added

- `takeover-dns` input (workers target, no default, needed only when a domain still has its own DNS records):
  `true` uploads the Worker, then per host deletes those records and at once binds the host as a Worker Custom
  Domain (zero downtime; the records are put back if the bind fails); `false` leaves the move to you. README:
  "Moving from Pages to Workers".
- Blocking static check `index.build_meta_early`: every page's `<meta name="build">` must end within the first
  8,192 characters, the window the live check reads, so a site's own late build meta fails before deploy. The core
  owns the window (`BODY_PREFIX_CHARS`, generated into the host's types).
- `[content] sources`: route glob → source path globs; a built page's lastmod is the newest commit of its sources.
  Pages left without a lastmod are named in a `page.no_lastmod` warning.
- Job summary: a Lighthouse table per gate, URL × performance, accessibility, best practices and SEO (median of the
  runs), with the failing audit ids.
- Post-deploy Lighthouse gate on the live URLs; on a failed live audit or gate, `rollback-on-failure: true`
  (required when deploying, no default) rolls production back to the version it served before.
- `[analytics] cloudflareWebAnalytics`: extends the site's CSP for the injected Web Analytics beacon; without
  it the live audit fails when the beacon is injected (`index.live_beacon`).
- Blocking static check `index.csp_robots`: the site's CSP must let the page fetch `/robots.txt`.

## [1.0.0] - Unreleased

### Added

- Composite GitHub Action `Avarok-Cybersecurity/geoharness@v1`: preflight, build, process, audit, Lighthouse,
  deploy, zone, verify, IndexNow and summary stages.
- Pure Rust core compiled to WebAssembly, shipped in `dist/core/`: markdown twins, fill-only head injection,
  robots.txt with Content Signals, `llms.txt`, `llms-full.txt`, `sitemap.xml`, `_headers`, IndexNow key,
  tagged URL Rewrite rules for `Accept: text/markdown`, live check plan and RAG inputs.
- Evidence-graded GEO audit with blocking access, indexability and delivery checks; config-less live audit
  (`geoharness audit <url>`).
- Adapters: static, command, npm, sveltekit-static, python, make, vite-prerender and worker-assets, with
  confidence-based detection.
- Lighthouse gate: 100 in all four categories, median of 3 runs.
- `deploy: false` dry run for pull requests: no Cloudflare API call, no credentials needed.
- Negotiate Worker fallback when the token has no zone access.
- `cloudflare-permissions.json`: permission groups per feature, probed in preflight.
- Product site and documentation at https://geo.avarok.net, built and deployed by GeoHarness itself.
- `rag` input reserved for v1.1 (LatticeDB in-browser search); `rag: true` fails clearly.
