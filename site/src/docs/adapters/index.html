Adapters and runtime detection

GeoHarness builds almost any static site. An adapter knows how to detect a kind of project, build it and list its pages; GeoHarness runs every adapter's detection, picks the most confident one and logs the evidence it found.

Updated 2026-11-19

How does GeoHarness choose an adapter?

  • Every adapter inspects the site directory and returns a confidence between 0 and 1 with the evidence behind it.
  • The highest confidence wins and its evidence is printed in the log.
  • When the top two tie, the run fails and names both, rather than guessing.
  • The adapter input overrides detection entirely.

Which adapters are there?

worker-assetsA wrangler config with assets.directoryBuilds, writes into the assets directory and deploys with your own wrangler config, so your Worker code and bindings stay in charge

pythontools/build.py, or pyproject.toml with a build-commandRuns the build; attaches markdown sources it finds to their pages

How are build commands run?

Commands run as an argument vector, never through a shell. Quotes group words; pipes, redirects, ;, &, $ and globs are rejected, so an input can never inject a command. Put multi-step builds in a script and call it.

Pages are every .html file in the output except 404.html. A page's lastmod is the date of the last commit that touched it (or its markdown source), never the time of the build.
