geoharness.toml reference

GeoHarness reads one file, geoharness.toml, from your site directory. Keys are camelCase, unknown keys are errors, and policy choices such as Content Signals are never defaulted.

Updated 2026-11-19 · Source: docs/config.md

Globs

content.exclude and llms.sections[].routes are matched against page routes: * matches within one path segment, ** across segments, everything else is literal (/blog/**, /docs/*/).

headers.immutable entries are written verbatim as _headers URL patterns, so * there is Cloudflare's splat, which crosses /.

lastmod

lastmod in sitemap.xml, the twin frontmatter and {{geo.lastmod}} is a git commit date, never the current time. Adapters date a page by the last commit of its output file when the output is committed, or of the markdown it was generated from (python adapter). Built output is usually gitignored, so for npm, vite-prerender, sveltekit-static and command sites map routes to their sources:

```toml

[content]

mainSelector = "main"

sources = { "/" = ["src/pages/index.astro"], "/blog/" = ["content/blog/", "src/layouts/Post.astro"] }

```

GeoHarness asks git for the newest commit touching each source glob (git log -1 -- ':(glob)<glob>', run in the site directory). A page takes the newest date among the globs of every entry whose route glob matches it, which overrides the adapter's date. A page no entry maps keeps the adapter's date; pages left with none are listed in one page.no_lastmod warning and their sitemap entries go without <lastmod>. There is deliberately no fallback to "the last commit anywhere in the site": that date moves for every edit, which would claim every page changed and teach crawlers to ignore the field.

Templates

Page HTML and adapter-supplied markdown may contain {{geo.build_id}}, {{geo.lastmod}} and {{env.NAME}} (whitespace inside the braces is allowed). NAME must be listed in env; reading an undeclared name is an error, never an empty string. Other {{...}} text is left untouched.

Example

This site's own configuration, which GeoHarness uses to build what you are reading:

# GeoHarness builds, audits and deploys its own site with this file (see .github/workflows/deploy.yml).

[site]
origin = "https://geo.avarok.net"
name = "GeoHarness"
language = "en"

[identity]
kind = "organization"
name = "Avarok Cybersecurity"
url = "https://avarok.net"
sameAs = ["https://github.com/Avarok-Cybersecurity"]

# An open-source tool's documentation is meant to be found, quoted and learned:
# search, answers and training all help people use it correctly.
[contentSignal]
search = true
aiInput = true
aiTrain = true

[[bots]]
group = "search"
tokens = ["Googlebot", "Bingbot", "OAI-SearchBot", "Claude-SearchBot", "PerplexityBot"]
allow = ["/"]

[[bots]]
group = "user"
tokens = ["ChatGPT-User", "Claude-User", "Perplexity-User"]
allow = ["/"]

[[bots]]
group = "training"
tokens = ["GPTBot", "ClaudeBot", "Google-Extended", "Applebot-Extended", "CCBot"]
allow = ["/"]

[[bots]]
group = "other"
tokens = ["*"]
allow = ["/"]

[content]
mainSelector = "main"

# Cloudflare injects the Web Analytics beacon on avarok.net; admit it in the CSP instead of failing on it.
[analytics]
cloudflareWebAnalytics = true

[llms]
summary = "GeoHarness is a GitHub Action that builds any website, serves markdown twins to AI agents for free on Cloudflare, gates on a GEO score and Lighthouse 100, deploys and verifies the live site."

[[llms.sections]]
title = "Docs"
routes = ["/docs/**"]

[[llms.sections]]
title = "Project"
routes = ["/", "/citations/"]
