GeoHarness documentation

GeoHarness is a composite GitHub Action: uses: Avarok-Cybersecurity/geoharness@v1. Everything it needs comes from its inputs and a geoharness.toml in your site directory; this page lists the inputs and outputs, and the pages below cover the rest.

Version 1.0 · Updated 2026-11-19

What is in the documentation?

  • geoharness.toml reference: every key, its validation and the few defaults (each with a reason).
  • Adapters and runtime detection: how GeoHarness finds and runs your build.
  • Cloudflare setup: the API token, the permission groups per feature, free-tier limits and fail modes.
  • GEO score and Lighthouse: every check, its evidence grade and its citations, and the Lighthouse policy.
  • Security model: what GeoHarness can touch and how it is contained.

Inputs

GitHub does not enforce required for composite actions, so GeoHarness validates every input itself in preflight and reports all problems at once. Inputs reach the CLI as environment variables and are never interpolated into a shell.

How do I run it on pull requests without deploying?

Set deploy: false. The run builds, processes, audits and runs Lighthouse, then stops: no Cloudflare API call, no deploy, no zone change, and no credentials are needed, so it is safe for pull requests from forks. The job summary says it was a dry run.

Can I run it outside GitHub Actions?

Yes. node dist/cli.mjs run runs every stage with the same INPUT_* environment variables the action sets; node dist/cli.mjs <stage> runs one stage, carrying state in GEOHARNESS_STATE_DIR. node dist/cli.mjs audit https://example.com/ audits any live URL without a configuration file, judging only what the site serves.
